{# The shared skeleton every resume template extends. WHY THERE IS A BASE AT ALL. Applicant tracking systems fail on a short, well-documented list of things: multiple columns, tables, graphics, text in the page header or footer, and section headings they do not recognise. That list is the same for all seven templates, so it is defined once, here, and no skin can accidentally opt out of it. What the skins are allowed to change is everything a parser does not read — typeface, weight, rules, spacing, the arrangement of a role's title and dates. The result is seven resumes that look genuinely different to a person and identical to a machine. Concretely, this file guarantees: · One column. No , no float, no grid with more than one track. · Contact details in the document body. Parsers routinely skip the page header region, so a name in @page margin content is a name that never arrives. · Standard section headings — "Work Experience", "Education", "Skills". A parser categorises by matching these strings; "Where I've Been" lands the whole section in the void. · Real text. No icons, no bar charts for skill levels, no images. A phone glyph parses as a random character, so the label is the word. · Reverse-chronological order, which is what every parser assumes. A skin overrides {% block styles %} and, if its layout calls for it, {% block role_entry %} and {% block header %}. Nothing else. #} {{ name }} — Resume {% block header %}
